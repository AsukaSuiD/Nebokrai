# ADR-0012: разрешение регистра дисковых путей ресурсов

Принято 22 сентября 2026 года при выделении курсора ресурсов в Shared.

Ресурсный путь нормализуется в ASCII lowercase, а поиск skill-cache открывал буквальный `SKILLS` и возвращал имена в нижнем регистре. На Linux обход мог найти файл, который последующее открытие уже не находило. Аналогичная зависимость от регистра существовала у `FilesInfo.ril` и `Package/*.pak`.

Общий `resolve_resource_path` сначала использует существующий точный путь. Если его нет, он разрешает компоненты по совпадению без учёта ASCII-регистра, сохраняя остальные символы. Единственное совпадение принимается; несколько совпадений вместо отсутствующего точного имени дают `InvalidData`. Выбор не зависит от порядка `read_dir`. Ошибки доступа передаются вызывающему.

Это инфраструктурный адаптер дисковых ресурсов. Нормализация ключей `.ril`/`.pak`, выбор пакета или файла, порядок reload и право доступа к пакету сохраняются. Ошибка пакетного источника не включает fallback на диск. Поведение остальных служб и их отдельных конфигурационных загрузчиков этим решением не меняется.

На точном пути достаточно проверки существующего объекта; обход каталогов нужен для разрешения различия регистра. Кэш имён не вводится, поэтому reload не зависит от устаревшего списка. Наблюдаемый прирост затрат на таком обходе требует runtime-измерения. Реализация и применение — в [ресурсных путях](../architecture/resources-and-configuration.md#курсор-ресурса).
