# ADR-0003: MSSQL с подключением через Tiberius

Принято. Область: хранение данных.

## Решение и причина

Сохраняем существующую MSSQL-модель и вызовы хранимых процедур. Tiberius заменяет Windows ADO/COM и обеспечивает подключение из Linux-кода.

Схема БД участвует в поведении игры: важны типы параметров, результаты процедур, порядок изменений и ошибки. Одновременная смена драйвера и модели данных смешала бы две задачи. Поэтому текущая работа восстанавливает поведение на существующей базе; миграция СУБД потребует отдельного решения.

## Последствия

SQL находится в [persistence/](../../server/rust/realm/src/persistence/). Мировые снимки и порядок сохранения принадлежат World; Game не получает параллельный путь прямой записи. [Описание БД](../architecture/database.md) связывает процессы, очереди и SQL-модули.

Отдельные исходные операции не объединяются автоматически в общую транзакцию. Например, [CRsCDKey](../../server/rust/realm/src/access/rscdkey.rs) сохраняет собственную последовательность ban-проверки, а [savedb](../../server/rust/realm/src/persistence/savedb.rs) допускает уже выполненные фазы при позднем отказе.

Схема оригинальной `userinfo` остаётся неизвестной: найденные backup её не содержат. [Представление локального стенда](../../deploy/hybrid/database-init.sh) даёт необходимую Login-проекцию поверх BillingDB; это отдельное допущение стенда. Установленные и открытые детали отмечены в описании БД.
