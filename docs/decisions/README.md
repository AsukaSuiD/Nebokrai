# Архитектурные решения

ADR фиксирует действующее инженерное решение: контекст, выбранную модель, сохраняемый контракт, причины, последствия, свидетельства и условия пересмотра. Это не журнал задач и не доказательство поведения оригинала само по себе. Если решение опирается на ещё не подтверждённый контракт, этот пробел указан явно.

| Решение | Область |
| --- | --- |
| [ADR-0001: спецификация системы в docs](0001-system-specification.md) | Где хранится подтверждённое знание и как отличать факт от готовности кода. |
| [ADR-0002: отделение игровой семантики от инфраструктуры](0002-semantic-boundary.md) | Почему допускается замена старого транспорта, платформы и библиотек. |
| [ADR-0003: сохранение MSSQL-контракта](0003-database-contract.md) | Почему Tiberius заменяет ADO, но схема и порядок побочных эффектов остаются предметом совместимости. |
| [ADR-0004: локальные сравнительные источники](0004-local-evidence.md) | Почему исторические реализации и Luvinia не смешаны с активным кодом и не отправляются в Git. |

Статусы `VERIFIED`, `PARTIAL`, `INFERRED` и `UNKNOWN` относятся к фактам оригинала по [правилам свидетельств](../reconstruction/evidence-and-contracts.md). Статус ADR — принятое решение Nebokrai — не повышает уверенность в этих фактах.
