# ADR-0006: гибридный стенд как ограниченный инструмент проверки

Статус решения: принято для текущего локального стенда. Область: эксплуатация и критерий готовности.

## Контекст

Активный Rust-пакет объявляет шесть серверных бинарников, но GameServer содержит существенные ещё не подтверждённые ветви. Локально имеется почти оригинальный Windows GameServer и данные, позволяющие держать его рядом с реконструированными процессами. Если назвать такой стенд «полностью восстановленным сервером», обнаруженные проблемы Rust GameServer будут скрыты и оценка готовности станет ложной.

## Решение

`deploy/hybrid` использует пять Rust-служб (Auth, Login, Billing, World, Misc) и Windows GameServer через Wine. Стенд предназначен для проверки конкретных межсерверных контрактов и клиентских сценариев, пока Rust GameServer исследуется отдельно. Rust Dockerfile **собирает** все шесть бинарников, но копирует в конечный образ пять; ошибка компиляции Rust GameServer всё равно остановит создание образа. Доступность портов в healthcheck не равна входу персонажа или успешной игре.

Локальные runtime-конфиги, EXE/PDB, ресурсы и backup БД остаются вне Git. Операционное имя SQL login `Miracle` сохраняется, поскольку исходные INI и восстановленные БД на него опираются; переименование этого идентификатора потребовало бы отдельной согласованной миграции. Имена контейнеров и пакет Nebokrai не меняют wire-контракт игры.

## Последствия и пересмотр

Результат проверки на гибридном стенде записывают с конкретной версией клиента, commit, вариантами EXE/PDB и данными, указывая, какие процессы были Rust, а какие — оригинальный runtime. Такой результат не переносится автоматически на Rust GameServer. Переход на полностью Rust-стенд возможен после компиляции, запуска и клиентских сценариев нового GameServer; текущий [аудит](../status/audit.md) эти уровни не подтверждает. Состав стенда и зависимостей задан в [операционной спецификации](../operations/hybrid-runtime.md) и [`compose.yaml`](../../deploy/hybrid/compose.yaml).
