# ADR-0005: отдельные владельцы World и Game

Принято. Область: персонаж, регион и сохранение.

## Решение и причина

Game ведёт живую симуляцию региона. World загружает и сохраняет персонажа, ведёт мировые организации, страны и маршруты. Между ними передаются сообщения с нужным состоянием.

Так региональная команда имеет определённое место исполнения, а долговременная запись проходит через одного мирового владельца. Прямой SQL из Game или перенос регионального боя в World создал бы дополнительные пути изменения данных и поменял момент эффектов.

## Последствия

При изменении сохраняемого состояния прослеживаем Game → сообщение → World → DB-модуль и обратную загрузку. При входе сохраняется последовательность `0x5FB01 → 0x7F901 → 0xBF401`; формат и отказные ветви описаны в [протоколе входа](../protocol/game-login.md).

Отдельный TCP-socket — текущий способ доставки. Для другой топологии потребуется сохранить владельцев, адресацию игрока, содержимое `GameSave`, очередность и результат потери соединения. До такого решения используется [межсерверный кадр](../protocol/transport.md).

Рабочая карта ответственности — [владение состоянием](../architecture/state-ownership.md), переходы персонажа — [жизненный цикл](../gameplay/player-lifecycle.md), запись — [БД](../architecture/database.md).
