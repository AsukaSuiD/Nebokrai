# Клиентские действия в GameServer

Эта страница описывает входные команды движения и применения навыка в достигнутом GameServer. Внешнее [TCP-обрамление](transport.md) проверяется до доменного обработчика; значения ниже — `MsgType` [внутреннего сообщения](message-header.md), а смещения полей отсчитаны от начала payload (`+0x10` от начала `CBaseMessage`). Все `long` исходного Windows-процесса — знаковые 32-битные little-endian слова. Владелец живого состояния — GameServer; клиент передаёт намерение, а не окончательное состояние персонажа.

Основание: комментарии [`shapemessage.rs`](../../server/rust/src/gameserver/appserver/message/shapemessage.rs) и [`skillmessage.rs`](../../server/rust/src/gameserver/appserver/message/skillmessage.rs) указывают точную пару `gameserver.exe`/`GameServer.pdb` и исходные `appserver/message/*.cpp`. Таблицы описывают поля и ветви текущего Rust-кода; соответствие всех байтовых ветвей оригиналу остаётся `PARTIAL`. Конкретные исходные свидетельства приведены рядом с правилами.

## Shape-команды `0x8F901..0x8F905`

| MsgType | Payload в порядке чтения | Размер | Назначение и обязательный порядок |
| --- | --- | ---: | --- |
| `0x8F901` | `u8 direction` | 1 | Изменить направление игрока → разослать `0xBF601` соседям → очистить эмоцию и разослать `0xBF611` → при активном contend отменить его в регионе и адресно уведомить игрока. |
| `0x8F902` | `i32 target_type`, `i32 target_id`, `i32 tile_x`, `i32 tile_y` | 16 | Только если разрешён `bAllowClientChangePos`: найти объект **в текущем регионе** → разослать `0xBF603` по его прежней позиции → вызвать перемещение через владельца региона. Отказ координат происходит после рассылки; перестановка шагов меняет наблюдаемое поведение. |
| `0x8F903` | `i8 move_mode`, `i8 direction`, `u8 rotation` | 3 | Шаг по направлению. Текущая базовая атака блокирует шаг и даёт `0xBF605`; несовпадение rotation вызывает `0xBF738`; мёртвый игрок не ставит шаг; затем очищается эмоция и назначение ставится в FIFO `CPlayerAI`. `move_mode != 2` меняет параметр назначения. |
| `0x8F904` | `i32 target_type`, `i32 target_id` | 8 | Запросить снимок фигуры из региона. Ответ `0xBF502` использует сериализатор фактического owner-а: player, ground goods, NPC или достигнутый summoned shape. |
| `0x8F905` | `i32 target_type`, `i32 target_id`, `i32 emotion_id` | 12 | Проверить цель-игрока, выполнить эмоцию и при публикации разослать `0xBF611`. При состоянии `ChangeBody` сначала отправляется `GS1038`, но проверка цели и попытка эмоции **продолжаются**. |

Rust до чтения полей требует точный размер payload из таблицы, затем связывает сообщение с `player_id` и `region_id`. Отсутствующий контекст или объект даёт прекращение этой команды без изменения чужого владельца. Для исходного EXE реакция на специально лишний/оборванный payload в этих ветвях не установлена (`UNKNOWN`); нынешнее строгое отклонение — техническая защита, а не заявленная идентичность ошибочного поведения.

`0x8F903` блокируется только когда активное действие AI — `Attack` **и** текущий skill ID равен `1`; ожидающая команда, фоновые навыки и произвольное состояние атаки этого условия не заменяют. Комментарий shape-обработчика связывает эту проверку с исходными адресами `CMoveShape::OnMessage` `0x004972D1`, `GetCurrentActiveAction` `0x0049731B` и проверки ID `0x0049732F` (`VERIFIED` для этой ветви). В комментарии эти адреса не названы RVA, поэтому такое обозначение здесь не присваивается. Почему старый клиент передаёт rotation отдельно от direction — `UNKNOWN`.

## Ответы на shape-команды

| MsgType | Направление и payload после заголовка | Условие |
| --- | --- | --- |
| `0xBF601` | Game → игроки вокруг: `u8 direction`, `i32 object_type`, `i32 object_id` | После принятия нового направления. |
| `0xBF611` | Game → игроки вокруг: `i32 object_type`, `i32 object_id`, `i32 emotion_id` | Очистка эмоции передаёт `0`; успешная эмоция — её ID. |
| `0xBF603` | Game → игроки вокруг старой позиции: `i32 target_type`, `i32 target_id`, `i32 tile_x`, `i32 tile_y` | До применения клиентской позиции. |
| `0xBF605` | Game → конкретный игрок: `i32 0`, `i32 0`, `i32 current_tile_x`, `i32 current_tile_y` | Отказ шага при базовой атаке или невозможности поставить назначение. |
| `0xBF738` | Game → конкретный игрок: `u8 server_rotation` | Rotation из `0x8F903` не совпал с серверным. |
| `0xBF502` | Game → конкретный игрок: `i32 object_type`, `i32 object_id`, переменный GUID по [базовому правилу](message-header.md), `i32 payload_len`, `payload_len` байт снимка, `i8 0` | Найден объект и его owner смог сериализовать снимок. Поля **внутри** снимка зависят от типа и здесь `PARTIAL`. |

Эти layouts следуют из writer-ов [`shapemessage.rs`](../../server/rust/src/gameserver/appserver/message/shapemessage.rs). `send_to_player` и региональная рассылка различаются адресацией; не следует считать круговой пакет подтверждением, что сам игрок получил отдельную копию. Точная реакция клиента на каждый из ответов — `UNKNOWN` без трассы исходного клиента.

## Применение навыков `0x90001..0x90005`

| MsgType | Поля в порядке чтения | Владелец исполнения |
| --- | --- | --- |
| `0x90001` | `i32 skill_id`, `i32 target_type`, `i32 target_id`, `i32 target_x`, `i32 target_y` | Проверки выученного навыка и цели → запрос игрока → canonical `CPlayerAI`; это не непосредственное применение урона. |
| `0x90002` | `i32 skill_id` | Завершает только совпадающий текущий навык; `IsEnd`/`End(true)` принадлежат конкретному экземпляру. |
| `0x90003` | `i32 skill_id`, `i32 level`, `i32 variant` | Формирует путь script family и запускает сценарий с контекстом игрока/региона. Для `530..545` путь `{id}0{level}.script`, для `960..962` — `{id}{variant}.script`, иначе `{id}.script`. Выключенная battle-fairy ветвь отклоняется уведомлением. |
| `0x90004` | `i32 skill_id`, `i32 skill_level`, `i32 target_type`, `i32 target_id`, `i32 target_x`, `i32 target_y` | Предметный навык идёт через отдельные проверки состояния/уровня, затем тот же игрок- и AI-маршрут. |
| `0x90005` | `i32 skill_id`, `i32 target_type`, `i32 target_id`, `i32 property_offset`, `i32 target_x`, `i32 target_y` | Навык боевой феи добавляет проверки её снаряжения и собственный target/AI-маршрут. |

Именно этот порядок и число `long` читает [`skillmessage.rs`](../../server/rust/src/gameserver/appserver/message/skillmessage.rs). В отличие от shape-команд здесь нет общей проверки точной длины: недостающее поле Rust отклоняет через `MissingField`, а лишние байты этой ветвью не интерпретируются. Исходный `GetLong` при усечении мог вернуть ноль без сдвига курсора; безопасная реакция Rust является осознанным отличием (`PARTIAL` для паритета ошибочного ввода). Дальнейший порядок cast, cost, Begin/AI/End и границы реализованных concrete owners описаны в [модели навыка](../gameplay/skills.md). Связанный урон и rounding — в [спецификации боя](../gameplay/combat.md).

`UNKNOWN`: полный клиентский автомат команд, наличие всех типов в конкретной версии клиента, layout payload вложенных shape-снимков, паритет malformed-входа и всех item/battle-fairy навыков. Наличие обработчика в Rust не доказывает, что все эти команды проходят end-to-end через текущий сервер.
