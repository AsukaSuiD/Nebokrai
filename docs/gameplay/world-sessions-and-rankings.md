# Мировые сессии и рейтинги

Эти владельцы работают в WorldServer и рассылают проекции на GameServer. Это **не** клиентская TCP-сессия: `CSession` здесь обозначает игровой процесс взаимодействия с участниками (`plug`), например команду или торговую сессию. **Статус:** `PARTIAL` для поведения оригинала: owner-комментарии связывают реализацию с `worldserver.exe`/`worldserver.pdb`, а перечисленные действия проверены по Rust; живой клиентский сценарий не проверен.

## Игровые сессии

`CSessionFactory` владеет registries session ID и plug ID. Типы session — normal и team; plug — normal, trader, продавец/покупатель персональной лавки, улучшение оборудования и участник команды. Базовая session хранит минимальное и максимальное число plug-ов, lifetime в миллисекундах, signed flags `started/ended/aborted` и порядок участника. `Start` запоминает wrapping tick; `AI` действует только при `started == 1`, `ended == 0`, `aborted == 0` и завершает ненулевой lifetime после `start + lifetime <= tick`. Вставка plug разрешена только в начатую не завершённую/не отменённую сессию, пока число участников меньше maximum. Источник: [`CSession`](../../server/rust/src/worldserver/appworld/session/csession.rs). **Статус:** `VERIFIED (reconstructed source)`; фактическое время при wrap/длительной паузе `PARTIAL`.

Фабрика в каждом AI-проходе удаляет null-запись, затем для недоступной session вызывает `Abort`, для уже завершённой — `End`; лишь иначе исполняет AI session и её plug-ов. Порядок обхода старой MSVC hash-map влияет на callbacks, поэтому Nebokrai воспроизводит bucket из `key ^ 0xDEADBEEF` и порядок signed ключей. Замена `std::list` на `Vec` и виртуальных указателей на owned Rust types допустима потому, что сохраняются видимый порядок ID, вызовов и wire; при duplicate ID Rust освобождает вытесненный объект вместо исходной утечки. Источник: [`CSessionFactory::ai`](../../server/rust/src/worldserver/appworld/session/csessionfactory.rs). **Статус:** `PARTIAL (EXE/PDB owner note + source)`; сравнение полного callback trace с оригиналом ещё не документировано.

Внутренние эффекты команды `TeamStarted`, `TeamEnded`, `KickPlayer` и изменение plug-state выводятся после virtual-вызова в его порядке. Например при завершении команды World посылает Game `0x7FD02` и только затем снимает team route; исключение участника посылает `0x7FD06` в Game, где расположен этот игрок. Очередь `WorldSessionEffect` в Rust служит техническим способом соблюсти исходный порядок при безопасном владении и не является самостоятельным игровым состоянием. Источник: [`drain_session_effects`](../../server/rust/src/worldserver/appworld/session/csessionfactory.rs). **Статус:** `VERIFIED (reconstructed source)`; все клиентские следствия `UNKNOWN`.

## Рейтинг игроков

`CPlayerRanks` хранит ordered записи `(player ID, имя, профессия, уровень, имя фракции)` и планирует ежедневную статистику на local time. При инициализации берёт время из настроек, подставляет текущую дату и переносит на следующий день **только при strict `< now`**. Callback после публикации добавляет сутки. При запуске расчёта список очищается до start-log, DB добавляет доступный префикс, затем end-log и рассылка могут состояться даже после DB `false`; значит старый список нельзя сохранять «на всякий случай» при отказе, если требуется совместимый порядок. Публикация в Game использует `0x7F801`, subtype `0x17`, signed count и записи в порядке вставки. Источники: [`CPlayerRanks`](../../server/rust/src/worldserver/worldserver/playerranks.rs), [`CGame::stat_player_ranks`](../../server/rust/src/worldserver/worldserver/game.rs), DB-owner [`rsplayer.rs`](../../server/rust/src/dbaccess/worlddb/rsplayer.rs). **Статус:** `PARTIAL (EXE/PDB owner note + source)`; исходная политика клиента для пустого рейтинга `UNKNOWN`.

## Почётные рейтинги

`CHonorRanks` хранит `history` и `current` для day/week/month/total отдельно по четырём странам. При смене дня маска включает daily и total; первого числа добавляется monthly, в понедельник weekly. Сначала текущие данные копируются в history; day/week/month после копии очищаются, total остаётся накопительным. Затем World ставит локальное сообщение `0x5FD0C` с маской и рассылает Game `0x7F801` с subtype `0x27..0x2A`; для total дополнительно идёт mask. Этот порядок важен: Game получает уже свернутую историю, а не промежуточный текущий список. Источник: [`CHonorRanks::on_new_day`](../../server/rust/src/worldserver/worldserver/honorranks.rs). **Статус:** `PARTIAL (EXE/PDB owner note + source)`.

При изменении почётного рейтинга existing entry обновляет показатели **без смены имени**, новая запись копирует имя только если видимая длина `< 20`. Список stable-сортируется по числу eliminations по убыванию, затем по уровню, и обрезается до десяти. Номер страны игрока `1..4` превращается в индекс `0..3`; нераспознанная страна пропускается. Сохранение делает отдельную DB-копию history/current с полным local timestamp; live-списки после передачи save-owner-у продолжают меняться. Источник: [`push_to_ranks`, `killed_one_player`, `generate_save_data`, `take_save_owner`](../../server/rust/src/worldserver/worldserver/honorranks.rs). **Статус:** `VERIFIED (reconstructed source)`, end-to-end с БД `UNKNOWN`.

**Открытые вопросы:** полный набор клиентских экранов для каждого subtype, соответствие DB сортировки player ranks наблюдаемому оригиналу при отказах, поведение всех session plugs при сетевом разрыве и byte parity полного `CSession` payload. Эти пробелы не закрываются тем, что owner-код реализован.
