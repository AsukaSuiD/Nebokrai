# Навыки GameServer

Это описание подтверждённых частей модели навыка, а не обещание, что все исходные навыки исполняются. Значения `VERIFIED`, `PARTIAL`, `INFERRED` и `UNKNOWN` определены в [правилах свидетельств](../reconstruction/evidence-and-contracts.md). Здесь свидетельство оригинала отделено от подключения нового Rust-кода. Сборка, работа сервера и совпадение с исходным клиентом этим описанием не проверяются.

## Владельцы и данные

| Владелец | Подтверждённая обязанность | Свидетельство и предел |
| --- | --- | --- |
| [World `CSkillFactory`](../../server/rust/src/worldserver/appworld/skills/skillfactory.rs) | Читает записи ресурсов и пишет начальный кэш уровней с ключом `id << 16 | level & 0xffff`; нулевые записи сохраняют позиции. | `VERIFIED`: верхний контракт owner-а с `worldserver.exe/worldserver.pdb`; это передача свойств, не исполнение навыка. |
| [Game `CSkillFactory`](../../server/rust/src/gameserver/appserver/skills/skillfactory.rs), [свойства уровня](../../server/rust/src/gameserver/appserver/skills/skillbaseproperties.rs) | Принимает кэш, хранит usage/value, имя, тип и соответствие ID конкретному классу. Вход кэша подключён в [обработчике начальной конфигурации](../../server/rust/src/gameserver/appserver/message/servermessage.rs). | `VERIFIED`: owner содержит источник EXE/PDB и адрес `QuerySkill` `0x00469870`; `Rebuild` подключён к `SKILL_LIST_SELECTOR`. Каталог 209 ID доказывает выбор класса, но не полный Begin/AI/End каждого класса. |
| [Зарегистрированный навык `CMoveShape`](../../server/rust/src/gameserver/appserver/moveshape.rs), [общая база](../../server/rust/src/gameserver/appserver/skills/kernel.rs) | Хранит экземпляр, уровень, данные исполнения, время последнего использования, visual и состояние Begin/End. `CPlayerAI` владеет командой выбора, а не копией экземпляра. | `VERIFIED` для достигнутых общих полей и порядка: верхние контракты owner-ов с EXE/PDB, `CState` `0x005DBCA0`, `CSkill` `0x004D8120`. `PARTIAL` для всех производных полей разных классов. |
| [Конкретные навыки](../../server/rust/src/gameserver/appserver/skills/), [зарегистрированный player cast](../../server/rust/src/gameserver/appserver/skills/playercast.rs) | Проверяют собственные условия, списывают ресурсы, исполняют каст, урон/состояния и visual, выбирают собственный End. | `PARTIAL`: есть реальные владельцы и общий dispatch, но не каждый ID и не каждая форма вызова имеют исполняемый путь. |

## Путь запроса и исполнения

| Стадия | Подтверждённое поведение | Статус, свидетельство и граница |
| --- | --- | --- |
| Вход клиента | [Диспетчер `skillmessage`](../../server/rust/src/gameserver/appserver/message/skillmessage.rs) принимает `0x90001` как пять 32-битных `long`: ID, тип и ID цели, X и Y. Оборванный пакет отклоняется. `0x90002` запрашивает завершение текущего навыка; `0x90003` выбирает путь сценария; `0x90004` передаёт уровень предметного навыка; `0x90005` проходит проверки боевой феи. | `VERIFIED`: контракт в owner-е `skillmessage.cpp` с парой `gameserver.exe/GameServer.pdb` и исполняемым decoder-ом. Изменение поведения повреждённого пакета в Rust явно оговорено owner-ом. Этот факт не является проверкой исходным клиентом. |
| Допуск команды | [Player owner](../../server/rust/src/gameserver/appserver/player.rs) сначала очищает emotion, затем проверяет изученный навык либо переданный item-level, выбирает self/point/object по полям запроса и проверяет доступность цели в регионе. Результат помещается в очередь канонического `CPlayerAI` через [игровой owner](../../server/rust/src/gameserver/gameserver/game.rs). | `VERIFIED` для показанных ветвей `0x90001/04`: EXE/PDB-контракт в верхнем комментарии `skillmessage`, исполняемые `request_player_skill_core` и `apply_skill_effect_journal`. Допуск команды ещё не равен успешному касту и не списывает универсальную цену. |
| Begin и каст | Планировщик [Game `CGame`](../../server/rust/src/gameserver/gameserver/game.rs) разрешает зарегистрированный экземпляр и передаёт его [player cast owner-у](../../server/rust/src/gameserver/appserver/skills/playercast.rs) либо отдельной подтверждённой ветви. [Kernel](../../server/rust/src/gameserver/appserver/skills/kernel.rs) представляет `Begin`, `Check`, `Calculate`, `Attack`, `Apply` и хранит время. | `PARTIAL`: общая последовательность подтверждена исходными owner-ами, а реальный переход между стадиями делает конкретный навык. Наличие enum не доказывает, что каждый навык проходит все пять стадий. В качестве конкретного пути [базовая атака](../../server/rust/src/gameserver/appserver/skills/baseattackruntime.rs) проходит Begin, проверку дальности и задержки, затем удар. |
| Цена и ограничения | Свойства читаются по ID/уровню. Проверки повторного использования, оружия, цели, MP, RP и допустимости прерывания принадлежат конкретным навыкам. Например, [Flash](../../server/rust/src/gameserver/appserver/skills/flash.rs) проверяет MP и RP, а при позднем отказе RP уже списанный MP не возвращает; [снаряды](../../server/rust/src/gameserver/appserver/skills/baseprojectilecast.rs) имеют иной порядок списания. | `PARTIAL`: прямые owner-контракты и Rust-переходы для этих семейств. `UNKNOWN` для единой формулы или общего момента оплаты всех 209 ID: такой контракт в коде не установлен, поэтому универсальный `cost-before-cast` здесь не утверждается. |
| Эффект | Конкретный owner управляет попаданием и visual; [приёмник атаки](../../server/rust/src/gameserver/gameserver/game.rs) выполняет защиту, изменение здоровья, реакцию ИИ и смерть. Состояния и области имеют свои владельцы, а не общий урон для всех навыков. | `PARTIAL`: связанный путь базовой атаки описан в `baseattackruntime`, но формулы, порядок callback-ов и visual зависят от семейства навыка. |
| Завершение | [Зарегистрированный End](../../server/rust/src/gameserver/appserver/states/skill.rs) сначала проводит производный cleanup; при ненулевом аргументе для Attack/State/Summon вызывает AfterUse, очищает контекст, записывает время использования и завершает visual. `End(0)` и Defense пропускают AfterUse и это обновление времени. Особый `Released` может оставить cast активным. | `VERIFIED` для общего `CSkill::End` (`0x004D84C0`) и порядка у достигнутых owner-ов; `PARTIAL` для полного concrete End каждого ID. Политики вызовов привязаны к [фабричному каталогу](../../server/rust/src/gameserver/appserver/skills/skillfactory.rs), а не выводятся только из категории. |
| Повторное применение | Экземпляр хранит `last_used_ms`; конкретные owner-ы берут задержку из usage `10005` и проверяют её через [общий `skill_is_restored`](../../server/rust/src/gameserver/appserver/skills/kernel.rs) как `last_used.wrapping_add(delay) <= now`. Новая отметка времени в общем End возникает при условиях строки выше. | `VERIFIED` для формулы и достигнутых вызовов, включая [Flash](../../server/rust/src/gameserver/appserver/skills/flash.rs); `PARTIAL` для всех навыков. Это не отдельная глобальная система cooldown и не доказательство правильного повторного применения каждого ID. |

## Границы интерфейса

Отдельный клиентский запрос `0x90002` завершает только совпадающий текущий навык, через [materialized End](../../server/rust/src/gameserver/appserver/message/skillmessage.rs). `0x90003` передаёт сценарий в [игровой script owner](../../server/rust/src/gameserver/gameserver/game.rs); это самостоятельный маршрут, не обязательная фаза каждого каста. Верхний комментарий `skillmessage` относит `0x90006` к исходному no-op, однако Rust-диспетчер в этом файле сопоставляет только `0x90001..0x90005`; маршрут `0x90006` в общем диспетчере требует отдельной проверки. Статус этого Rust-маршрута — `UNKNOWN`, а не подтверждённый no-op.

Главная незакрытая граница — полнота по каждому навыку и каждой перегрузке Begin/AI/End. [Исполнитель GameServer](../../server/rust/src/gameserver/gameserver/game.rs) явно отклоняет неподдержанный ID или вариант цели. `INFERRED`-переходов эта страница не добавляет: без прямого owner-свидетельства сходство двух навыков не считается контрактом. Проверки сборки, реального запуска, ресурсов/БД и исходного клиента для описанных путей здесь **не проводились**.
