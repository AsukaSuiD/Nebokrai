# История Nebokrai / Project history

**English summary.** Nebokrai reconstructs the server behavior of *Поднебесье* (Miracle) for preservation and interoperability. The available Git record starts on 18 August 2026; this page makes no claim about earlier work. It documents binary research, separate C++ and Rust work, a hybrid reference setup, and six Rust/Linux services. These milestones establish development activity, not complete client compatibility.

## Исходная проблема и технический контекст

У legacy-клиента уже есть ожидания: куда подключаться, как получать персонажа, какие поля читать и когда переходить в игровой режим. Исходная серверная платформа разделяла вход, мировые данные, региональную симуляцию, платежи и аукцион между процессами. Nebokrai восстанавливает эти наблюдаемые границы, чтобы сохранить поведение системы в поддерживаемой реализации.

Материал исследования — оригинальные EXE с соответствующими PDB. Символы помогают сопоставить функции и структуры, статический анализ — найти ветви поведения. Полные оригиналы и декомпилят остаются локальными. Публичный результат — собственный код, спецификации и объяснение оснований. Исторические имена в коде сохраняют связь с исследованием, но не означают поставку исходников первоначального разработчика.

В этой последовательности Auth/Login восстанавливают путь учётной записи и отложенные ответы. World связывает его с загрузкой и сохранением персонажа, а Game — с клиентским снимком и региональной симуляцией. На проверке 20 сентября список персонажей уже был доступен, но загрузка упиралась в различия схемы БД; после исправления чтения данных удалось зарегистрировать игрока в Game. Затем проявились ошибки клиентского снимка. Эти наблюдения подробно разделены в [аудите выбора персонажа](../status/audit.md#выбор-персонажа-в-локальном-клиенте). Появление исполняемого файла и подтверждение всего пути — разные этапы.

Проверить датированные изменения можно локально через `git log --reverse --date=short --format="%ad %s" main` и по затронутым каталогам. Русские сообщения коммитов являются частью реальной истории разработки. Таблица описывает только доступную историю и не заменяет подробный журнал.

## Почему Rust и Linux

Rust делает владение живыми объектами и ресурсами явным, а Linux предоставляет целевую среду современных серверных процессов. Tokio и Tiberius заменяют инфраструктуру, сохраняя значимые контракты совместимости. Это позволяет разделить вопрос «какой результат ожидает клиент» и вопрос «как поддерживать реализацию сегодня». Причины и ограничения — в [руководстве разработчика](../development.md) и [ADR](../decisions/README.md).
