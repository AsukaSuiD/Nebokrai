# Nebokrai

**Независимая реконструкция серверной платформы закрытой MMORPG «Поднебесье» (Miracle) на Rust под Linux.**

Цель Nebokrai — сохранение программного поведения игры и совместимость с её legacy-клиентом: форматов сообщений, игровых правил, сохранения данных и порядка наблюдаемых действий. Это современная собственная реализация, а не публикация исходников первоначального сервера и не заявление о полной совместимости.

Проект соединяет серверную разработку с документированным исследованием. Символы и анализ бинарников помогают найти поведение, но неизвестное остаётся неизвестным, пока для него нет достаточного основания. Такой материал полезен разработчикам MMO, Rust-серверов, совместимых протоколов и preservation-проектов независимо от знакомства с самой игрой.

## История и назначение

Доступная история реконструкции в Git начинается **18 августа 2026 года**. Она фиксирует исследования EXE/PDB, отдельный C++-проход, переход к Rust/Linux, гибридный стенд и запуск шести Rust-процессов. [Техническая история](docs/overview/history.md) связывает эти этапы с изменениями репозитория и наблюдениями; более ранние даты здесь не устанавливаются.

## Архитектура

Основной сервер — один Rust-пакет с шестью исполняемыми файлами:

| Служба | Назначение |
| --- | --- |
| Auth | Проверка учётной записи в соответствующем маршруте авторизации. |
| Login | Приём клиента, выбор маршрута проверки и мира. |
| World | Загрузка и сохранение персонажей, мировое состояние, маршрут к Game. |
| Game | Живая региональная симуляция: движение, бой, предметы, NPC и игровой клиент. |
| Billing | Баланс и операции покупки/обмена. |
| Misc | Аукцион и его взаимодействие с World. |

Game владеет живым состоянием региона; World отвечает за мировое сохранение. Обмен сохраняет legacy TCP-форматы. Tokio обслуживает сеть и задачи, Tiberius — Microsoft SQL Server. Современная инфраструктура не отменяет значимый порядок сообщений, таймеров, блокировок и частичных эффектов БД.

Начните с [обзора архитектуры](docs/overview/architecture.md) и [пути одного игрока](docs/overview/player-journey.md). Подробности — во [владении состоянием](docs/architecture/state-ownership.md), [протоколе](docs/protocol/README.md) и [ADR](docs/decisions/README.md).

## Что подтверждено

Nebokrai остаётся реконструкцией в работе. По [подробному аудиту](docs/status/audit.md) на 21 сентября 2026 года шесть Rust-служб собирались под Linux и запускались вместе. Legacy-клиент достиг списка персонажей; последующий выбор привёл к загрузке персонажа и регистрации игрока в Game.

Стабильная игровая сессия пока **не продемонстрирована**. После исправлений протокола и движения соответствующие клиентские сценарии ещё нужно повторить. Полное сохранение между сессиями, переходы регионов, аукцион, платежи, всё SQL-поведение и длительная нагрузка этим запуском не подтверждены. [Краткий статус](docs/overview/status.md) помогает выбрать нужную подробность, [направления дальнейшей работы](docs/overview/roadmap.md) описывают реальные пробелы без обещанных сроков.

Ближайший шаг — повторить вход до управляемого персонажа и движение на сборке с последними исправлениями.

`VERIFIED`, `PARTIAL`, `INFERRED` и `UNKNOWN` относятся к конкретным контрактам и их основаниям. Подтверждение поведения оригинала, наличие реализации, успешная сборка и фактическая работа с клиентом — разные факты.

## Как восстанавливается поведение

Цепочка исследования: идентифицированный EXE и matching PDB → Ghidra → кандидат поведения → проверка инструкций, парной стороны протокола или наблюдаемого сценария → спецификация и собственная реализация. Сам декомпилят не доказывает контракт. [Обзор метода](docs/reconstruction/overview.md), [правила свидетельств](docs/reconstruction/evidence-and-contracts.md) и [разбор входа в регион](docs/reconstruction/case-study-region-entry.md) объясняют этот процесс на практике.

## Начало разработки

Откройте [портал документации](docs/README.md), затем [руководство разработчика](docs/development.md) и [карту проекта](docs/architecture/workspace.md). Основной рабочий язык — русский, включая сообщения коммитов. Английский README и краткие summaries делают проект доступным более широкой аудитории; подробные страницы не дублируются целиком на двух языках.

На Linux установите toolchain из [rust-toolchain.toml](server/rust/rust-toolchain.toml). Из корня репозитория:

```sh
cd server/rust
cargo check --locked --lib --bins
```

[Руководство сборки](docs/operations/build.md) описывает зависимости и Docker Desktop/PowerShell. Текущий слой процессов рассчитан на Linux. Для запуска нужны локальные конфигурации, совместимые ресурсы и данные БД; каждый процесс читает файлы из своего рабочего каталога. Клон репозитория сам по себе не является готовой игровой поставкой. См. [Rust-стенд](docs/operations/rust-runtime.md) и отдельный [гибридный стенд](docs/operations/hybrid-runtime.md) с локальным оригинальным GameServer под Wine.
