# Nebokrai

`Nebokrai` — основной рабочий проект реконструкции Miracle/«Поднебесья» в чистый и поддерживаемый исходный проект.

Проект не копирует старые попытки целиком и не вводит новую игровую архитектуру без необходимости. Исходные owners, классы, структуры данных, протоколы, порядок действий и игровая семантика сохраняются настолько близко к оригиналу, насколько это подтверждается исходными материалами.

## Структура

`server/` содержит новую C++-реконструкцию серверной части. Исходный код сервера находится в `server/src/` и разделён по реальным владельцам и компонентам:

```text
server/
├─ CMakeLists.txt
├─ src/
│  ├─ nets/
│  ├─ public/
│  ├─ auth/
│  ├─ login/
│  ├─ billing/
│  ├─ misc/
│  ├─ world/
│  └─ game/
└─ resources/
```

Новые каталоги и абстракции создаются только когда для них появляется реальная ответственность в проекте.

## Источники реконструкции

При восстановлении серверного кода используется следующий порядок доверия:

1. оригинальные EXE/PDB;
2. точечный анализ в Ghidra, когда EXE/PDB и уже известного кода недостаточно;
3. `archive/Miracle_server_linux` как рабочий, но недоверенный C++-донор предыдущей попытки;
4. сохранённая Rust-реконструкция как дополнительный справочник по ранее найденным контрактам и различиям.

Код из доноров не считается правильным автоматически только потому, что когда-то запускался. Перед переносом он сверяется с оригиналом и приводится в чистый вид.

## Библиотеки

Зрелые библиотеки используются для универсальных инженерных задач, которые не являются особенностью Miracle: сетевой I/O, логирование, форматирование, конфигурация, стандартное сжатие и хеширование, работа с БД и другие инфраструктурные задачи.

Специфические контракты Miracle библиотеками не подменяются. Собственный wire-протокол, форматы сообщений, игровые структуры, алгоритмы и другие особенности оригинала восстанавливаются явно.

Критерий простой: особенность Miracle восстанавливается; универсальная инженерная задача по возможности передаётся подходящей зрелой библиотеке вместо новой самописной реализации.

## Документация кода

Основная документация реконструкции находится в самих owner-файлах. Верхний комментарий файла фиксирует происхождение, существенные подтверждённые особенности, важные различия вариантов, технические замены и оставшиеся неизвестности.

Отдельные карты, журналы прогресса, отчёты и вспомогательные `.md` не создаются без явной необходимости.
